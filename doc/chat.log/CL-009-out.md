Да, могут. И это как раз одна из причин, почему стоит заранее выбрать единое правило.

В Ada имя библиотечной единицы и имя файла часто связаны правилами конкретного компилятора.

Например:

```ada
package AVTT_Config is
end AVTT_Config;
```

Современный GNAT ожидает что-то вроде:

```text
avtt_config.ads
```

и автоматически сопоставляет имя пакета с именем файла.

Если же файл называется:

```text
avtt_cfg.ads
```

то GNAT уже не найдёт пакет без дополнительных настроек или специальных соглашений.

---

Для старых компиляторов ситуация ещё интереснее.

### Meridian Ada

Во многих старых Ada-системах имя файла вообще не было частью стандарта Ada.

Компилятор работал со своими библиотеками объектов и мог хранить:

```ada
AVTT_Config
```

непосредственно в собственной библиотеке.

Тогда файл мог называться как угодно.

---

### Janus Ada

Обычно более гибок, но всё зависит от версии и режима сборки.

---

### GW-GNAT

Здесь уже действует GNAT-соглашение по именованию.

То есть:

```ada
package AVTT_Config
```

лучше хранить в:

```text
avtt_config.ads
```

---

## Поэтому я бы рекомендовал

Не делать так:

```ada
package AVTT_Config
```

↓

```text
avtt_cfg.ads
```

Потому что возникает дополнительное отображение:

```text
Config → cfg
Object_IDs → objids
Renderer → rndr
```

которое нужно помнить разработчикам и инструментам.

---

## Более безопасный вариант

Пакет:

```ada
package AVTT_Config
```

Файл:

```text
avtt_config.ads
```

---

Пакет:

```ada
package AVTT_Object_IDs
```

Файл:

```text
avtt_object_ids.ads
```

---

Пакет:

```ada
package AVTT_Renderer
```

Файл:

```text
avtt_renderer.ads
```

---

Такой стиль:

- понимает GNAT;

- понимает GW-GNAT;

- понимают современные IDE;

- легко генерируется скриптами;

- не требует таблиц соответствия.

---

## А что насчёт ограничений DOS 8.3?

Если вдруг появится задача собирать AdaVTT на системе, где доступны только имена файлов формата 8.3, тогда придётся вводить отдельную схему отображения.

Например:

```text
avtcfg.ads
avttyp.ads
avtobjid.ads
avtevent.ads
```

Но я бы **не проектировал основной репозиторий под 8.3**.

Лучше сделать специальный слой совместимости:

```text
platform/
└── dos83/
```

или отдельный набор скриптов для упаковки исходников под такие системы.

Иначе весь проект будет страдать из-за ограничения, которое большинству целевых компиляторов уже не актуально.

---

Поэтому для AdaVTT я бы зафиксировал простое правило:

| Пакет             | Файл                  |
| ----------------- | --------------------- |
| `AVTT_Config`     | `avtt_config.ads`     |
| `AVTT_Types`      | `avtt_types.ads`      |
| `AVTT_Object_IDs` | `avtt_object_ids.ads` |
| `AVTT_Events`     | `avtt_events.ads`     |
| `AVTT_Memory`     | `avtt_memory.ads`     |

То есть **имя файла — это просто имя библиотечной единицы в нижнем регистре**, без дополнительных сокращений. Это наиболее совместимый и наименее проблемный вариант для GNAT-семейства и большинства других Ada-компиляторов.
